# md301ctl —— 华硕 ProArt MD301 鼠标离线配置工具

不联网、不开浏览器，直接通过 HID 与鼠标（或 2.4G 接收器）通信，实现
`https://gearlink.asus.com.cn/zh-cn`（Gear Link 网页版）里对 MD301 的设备设置功能。

**不想自己编译**：到 [Releases](https://github.com/ddordie/md301ctl/releases)
下载 `md301ctl.exe`，双击即用（Windows x64，单文件零依赖，无需 Rust 工具链）。

协议是从 Gear Link 网页版的 JS 逆向出来的，并在真机上逐条读写验证过
（读到 `hidtrace5b.json` 级别的原始报文对比）。

界面有两套：默认的零依赖 Win32 窗口（就是 exe 里那个），以及 [gui-qt/](gui-qt/)
下用 PySide6 + QML 重写的版本（协议同一份实现，Qt 只当壳——方便照设计稿做界面）。

## 为什么需要它

官方网页版必须联网（要下载对应 PID 的协议模块并校验），没网就改不了 DPI／按键。
本工具把这些功能搬到了本地：一个 exe，插上鼠标就能用。

## 编译

需要 Windows + MSVC 工具链（Rust stable）：

```bash
cd md301ctl
cargo build --release
# 产物: target/release/md301ctl.exe
```

**零第三方依赖**，不需要 crates.io 联网，也不需要 C 编译器（FFI 直接调用
`setupapi` / `hid.dll` / `kernel32`）。

> 在 git-bash 里编译若报 `LNK1104: cannot open file 'C:\c\Users\...'`，
> 是该 shell 的小写 `tmp` 环境变量被 MSYS 路径污染，用：
> `env -u tmp TMP='C:\Users\<你>\AppData\Local\Temp' cargo build --release`

## 图形界面（Windows 原生版，日常用这个）

直接**双击 `md301ctl.exe`**，或运行 `md301ctl gui`，会开一个窗口：

- 顶栏：指示灯 + 「已连接 / 未连接」+ 配置档下拉 + 切换 + 电量（按电量变色，充电时显示闪电）
- 鼠标插画四周 10 个按键映射下拉：左键 / 右键 / 滚轮点击 / 侧键前进 / 侧键后退 / DPI 切换键 /
  向上滚动 / 向下滚动 / **向左滚动 / 向右滚动**（后两个是侧边滚轮的左右方向，走设备的扩展按键表）
- DPI 设定：3 档滑块 + 数值 + 「设为当前」（当前档用强调色，其按钮置灰）
- 回报率（125/250/500/1000 Hz）、按键响应（12/16/20/24/28/32 ms）
- 电源：休眠时间（1/2/3/5/10 分钟与「永不」）+ 低电量提醒阈值
- 应用按键映射 / 应用 DPI / 保存到 Flash / 恢复出厂（有二次确认）

界面按设计稿（1280×720 画布）实现：静态层是 `gui-qt/assets/ui-bg.svg`（含鼠标插画、
引线、卡片底、静态标签），会随设备状态变化的控件都在 `gui-qt/qml/Main.qml` 里按设计稿
坐标摆放（坐标表 `qml/proto.js`）。自动刷新**始终开启**（没有开关）：读数成功不刷状态栏，
底部只显示写操作结果与错误。按键映射是「先选后应用」——改完点「应用按键映射」才写设备。

## 命令行用法

```
md301ctl --help                 完整命令列表
md301ctl list                   列出检测到的 ASUS HID 接口
md301ctl status                 一次输出 info + 电量 + 性能 + 按键
```

常用操作：

```bash
md301ctl dpi                              # 看 4 档 DPI 与当前生效档
md301ctl dpi set 2 1600                   # 把第 2 档改成 1600（50 的倍数，官方上限 8000）
md301ctl perf response 5                  # 按键响应 32ms（0–5 = 12/16/20/24/28/32 ms）
md301ctl dpi switch 2                     # 立即切到第 2 档
md301ctl perf polling 1000                # 回报率 125/250/500/1000（MD301 只有这 4 档）
md301ctl buttons map 侧键后退 滚轮点击      # 改按键映射（第一个参数是设备上的按键，见 `buttons`
                                          # 输出的左键/右键/滚轮点击/侧键前进/侧键后退/DPI 切换键/
                                          # 向上滚动/向下滚动/向左滚动/向右滚动，或 0x1F0 代码；
                                          # 旧名字（中键/左侧后键/滚轮上滚…）仍然可用；
                                          # 第二个参数是功能码，见 `buttons names`）
md301ctl buttons names                    # 列出全部可用功能码
md301ctl profile set 2                    # 切换配置档
md301ctl battery                          # 电量/充电/休眠/低电量阈值
md301ctl power set --sleep 0-4|255 --low 0-100 3 --low 15     # 休眠 5 分钟，低电量提醒 15%
md301ctl perf save                        # 写入 Flash 永久保存（断电保持）
md301ctl monitor 30                       # 监听设备主动上报的事件
```

任何命令都可以加 `--json` 输出机器可读结果，方便脚本调用：

```bash
md301ctl battery --json
{"battery":63,"charging":false,"sleep_index":1,"low_power":20,...}
```

前端（`gui-qt/`）只依赖两条命令：

```bash
md301ctl spec --json      # 静态规格：能力表 + 休眠档 + 按键名 + 156 个功能码（不碰设备，<0.1s）
md301ctl status --json    # 实时快照：device/power/dpi/perf/buttons 一个对象一次给全（约 0.7–2s）
md301ctl buttons --json   # 10 个按键槽位 → 当前功能码：{"extReadOk":true,"buttons":{...,"向左滚动":494,"向右滚动":495}}
```

> 耗时说明：`status` 早期要 7.3 秒，原因是设备**不支持**的查询（传感器模式、附加按键表）
> 也会走 4 轮重试，白等 ~5.8 秒。现在这类探测型读取只试一次、超时 600ms，
> `perf` 6.1s→0.9s、`buttons` 6.4s→1.4s、`status` 7.3s→0.7–2.1s。

## MD301 实际支持的设置

以设备真机应答为准（网页端也是按同一套能力表显示对应面板）：

| 功能 | 命令 | 状态 |
|---|---|---|
| 设备信息（固件/配置档/当前 DPI） | `info` | ✅ 已验证 |
| 3 档 DPI 读/写/切换 | `dpi` | ✅ 写入并读回验证（档位数固定 3 档） |
| X/Y 分离 DPI | `split` | ✅ 已读取 |
| 回报率 | `perf polling` | ✅ 只有 125/250/500/1000 四档（与官方页面一致） |
| 按键映射（基础/扩展/附加） | `buttons` | ✅ |
| 电量/充电/电池类型/休眠/低电量/满电灯效 | `battery` / `power set` | ✅ |
| 配置档切换与保存、恢复出厂 | `profile` | ✅ |
| 事件监听（按键状态/在线心跳） | `monitor` | ✅ |
| 按键响应 | `perf response` | ✅ 6 档：`0–5` = 12/16/20/24/28/32 ms（与官方一致） |
| 直线修正 / 角度微调 | `perf snapping` 等 | ⚠️ 命令被接受但值不变（本机型不支持） |
| 传感器模式 / 帧率 / DPI 灯效 / 动同步 | — | ❌ 设备无应答（不支持） |

命令仍然保留，因为同一协议族里别的华硕鼠标支持它们。

## 协议要点（逆向所得）

- 控制通道：HID 接口 **Usage Page `0xFF01` / Usage 1**，report ID `0`，
  写 **65 字节**（1 字节 report ID + 64 字节载荷），读 **64 字节**。
- 事件通道：**Usage Page `0xFFC1` / Usage 1**（仅输入）。
- 帧格式：`[命令, 键/子命令, 索引低, 索引高, 载荷...]`；应答按前 4 字节回显匹配。
- 命令：`0x12` 读、`0x51` 写、`0x50` 配置档/保存。
- 主要地址（键, 索引）：
  - 设备信息 `12 00 00`、按键映射 `12 05 00`、性能信息 `12 04 00`、
    分离 DPI `12 04 02`、电源 `12 07 00`
  - DPI 写入 `51 31 <档位-1>`、切换 `51 31 09`、回报率 `51 31 04`、
    按键映射写入 `51 21 00`、电源写入 `51 37 00`
  - 配置档切换 `50 02 <档位-1>`、保存到 Flash `50 03 00`、恢复出厂 `50 40 00`
- DPI 编码 = `DPI/50 - 1`（16 位小端），所以 DPI 必须是 50 的倍数。
- VID `0x0B05`，PID `0x1CD3`（2.4G 接收器）/ `0x1CD5`（有线）。

## 已知行为与排错

- **鼠标射频休眠时不会正常应答**，只回一个占位报文（实测：`12 00 00 00 20 …`，
  配置档数为 0，其余字段全是假的）。工具会自动重试并提示"请移动鼠标唤醒后重试"。
- **休眠保护（重要）**：读取时会校验占位应答，识别到就直接报错，绝不把假数据当数据
  渲染；界面里所有写操作（应用 DPI / 应用按键映射 / 回报率 / 按键响应 / 切换配置档）
  在写入前都会先确认设备醒着，休眠时**拒绝写入**并提示先移动鼠标唤醒。
  这是为了防止"把占位应答里的数字当成目标值写进设备"：休眠时界面里会显示
  固件 0.0.32 / 配置档 1-0 / 档1=1100 这类假数据（实测），此时点"应用"就会把
  假数据当目标值下发。
- **界面只在"值真的变了"时才写入**：Windows 的 `WM_COMMAND` 通知码在高 16 位，
  早期版本没区分通知码，导致"展开下拉框"也会把界面里显示的值写回设备（实测到的行为）。
  现在只认 `CBN_SELCHANGE`/`CBN_SELENDOK`，并且选中值 == 设备当前值时不写。
- 刷新界面（启动/重新读取）本身不会写任何设置。
- 修改后如果希望断电保持，执行 `md301ctl perf save`（或 `profile save`）。
- `profile reset-all --yes` 会清空全部配置档并恢复出厂，不可撤销。
- `list` 能看到接口但 `info` 报"无应答"：多半是鼠标没开机 / 没在 2.4G 模式，
  或接收器没插好。
- **DPI 范围 100–8000（步进 50）、固定 3 档**：官方网页对该型号的能力表是
  `{maxDPI: 8000, maxDpiCount: 3, minDpiCount: 3}`，滑块 `min:100, max:8000, step:50`。
  设备虽然能存下更大的值（实测 26000 也能写入并读回），但官方从不提供，所以本工具
  与官方保持一致，超出范围直接报错。
- **"档位数"固定 3 档**：`minDpiCount == maxDpiCount == 3`，官方 UI 也不给改，
  所以界面里只作展示（不再提供下拉修改，避免写坏）。
- 第 4 个 DPI 槽位是未启用哨兵，写入会被设备忽略（实测），界面只显示 3 档。
- **按键响应是 6 档而不是 2 档**：官方 bundle 里的表是
  `Ec = [{value:0,label:"12"},{value:1,label:"16"},…,{value:5,label:"32"}]`，
  滑块 `min:0,max:5,step:1` —— **写入值就是档位索引**，`0` 不是"默认/关闭"而是 12ms。
- **回报率只有 4 档**（125/250/500/1000）。协议枚举里的 2000/4000/8000 是给带 Booster 的
  或 ROG 8K 机型（P723/P724/P725/P728/P729/P731）用的，官方 JS 对 MD301 只给出 4 档。
  实测往本机型写 2000 能被存下来并读回，但那是"存了个值"，不代表真按 2000Hz 上报，
  官方页面也从不提供——所以本工具现在只允许这 4 档。

- **低电量提醒 = 鼠标本体红灯闪烁（实测）**：阈值存在设备里（`51 37 00` 的载荷第 3 字节），
  低于阈值时**鼠标本体的灯闪一阵红灯后熄灭**——纯固件行为，与主机/网页无关。
  主机侧读不到任何"已提醒"状态位：把阈值设成 10% 与 65%（当前电量 61%）两种状态各读一次，
  解析出的字段除阈值本身**完全一致**（电量/充电/电池类型/满电灯效/电压都一样）。
  所以本工具（与 Gear Link 一样）不会弹低电量通知——官方 FAQ 也写明「設置通知」不在
  Gear Link 支持范围内。要做主机端提醒，只能自己用「电量 < 阈值」判断。
  验证方法：把阈值临时改到高于当前电量、请人盯着鼠标看，然后改回原值（只是 RAM 改动，
  不执行 `perf save` 就不会写进 Flash）。
- **休眠档位共 6 档**：官方 `Xs = {0:"1 分鐘",1:"2 分鐘",2:"3 分鐘",3:"5 分鐘",4:"10 分鐘",255:"永不"}`，
  含 `255 = 永不`（早期版本漏了这一档，已在 `spec --json` 补上）。
